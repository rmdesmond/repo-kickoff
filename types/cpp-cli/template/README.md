## Testing

```sh
ctest --test-dir build --output-on-failure   # CMake 3.20 or later
(cd build && ctest --output-on-failure)      # any CMake version
tests/smoke.sh                               # builds in a temporary folder, checks the program, runs ctest
```

The unit tests are built by default and registered with `gtest_discover_tests`, so each test shows up in ctest on its own. They need GoogleTest: without it, configuring stops with a message saying how to get it. To build only the program, configure with `-D{{NAME_SNAKE}}_BUILD_TESTS=OFF`. `tests/smoke.sh` always builds and runs the unit tests, and never downloads anything.

## Getting GoogleTest

The build looks for an installed copy first (`find_package(GTest)`). Install one with:

```sh
brew install googletest              # macOS, Homebrew
sudo apt install libgtest-dev        # Debian, Ubuntu
```

Or let CMake download it, by opting in when you configure:

```sh
cmake -S . -B build -D{{NAME_SNAKE}}_FETCH_GOOGLETEST=ON
```

This downloads GoogleTest 1.15.2 with `FetchContent`, checked against its SHA-256, and only when no installed copy is found. The option is off by default, so a normal build never touches the network, and `tests/smoke.sh` always turns it off.

- C++17, without compiler extensions (`CMAKE_CXX_EXTENSIONS OFF`).
- The library is static and private to the project; only the program is installed.
- Warnings (`-Wall -Wextra -pedantic`) are on for gcc and clang, but don't fail the build.
- `{{NAME_SNAKE}}::run()` takes the arguments (without the program name) and the output and error streams, so tests capture output with string streams instead of touching the real stdout.
- Option parsing is hand-written: with only `--help` and `--version` there's nothing to justify a dependency. Swap in a parsing library when the program grows real options.
