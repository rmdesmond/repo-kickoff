## Requirements

- CMake 3.14 or later
- a C11 compiler: Apple clang (Xcode Command Line Tools) on macOS, gcc or clang on Linux
- for the unit tests: a C++17 compiler and GoogleTest (see [Getting GoogleTest](#getting-googletest)). Projects that use the library don't need either

## Building

Build in a separate folder, never in the source tree:

```sh
cmake -S . -B build
cmake --build build
```

This builds `build/lib{{NAME_SNAKE}}.a`. For a shared library, configure with `-DBUILD_SHARED_LIBS=ON`.

## Testing

```sh
ctest --test-dir build --output-on-failure   # CMake 3.20 or later
(cd build && ctest --output-on-failure)      # any CMake version
tests/smoke.sh                               # the whole round trip, in a temporary folder
```

Without GoogleTest, configuring stops with a message saying how to get it. To build the library without its tests, configure with `-D{{NAME_SNAKE}}_BUILD_TESTS=OFF`.

## Getting GoogleTest

The build looks for an installed copy first (`find_package(GTest)`). Install one with:

```sh
brew install googletest              # macOS, Homebrew
sudo apt install libgtest-dev        # Debian, Ubuntu
```

Or let CMake download it, by opting in when you configure:

```sh
cmake -S . -B build -D{{NAME_SNAKE}}_FETCH_GOOGLETEST=ON
```

This downloads GoogleTest 1.15.2 with `FetchContent`, checked against its SHA-256, and only when no installed copy is found. The option is off by default, so a normal build never touches the network, and `tests/smoke.sh` always turns it off.

## Choices made for you

- Every public C name starts with `{{NAME_SNAKE}}_`; the header wraps its declarations in `extern "C"` so C++ can include it.
- The library is static by default (`BUILD_SHARED_LIBS=OFF`). Shared builds work on macOS and Linux; Windows DLLs would need export macros, which aren't set up.
- The tests are GoogleTest, compiled as C++17, which recent GoogleTest releases require. They're built only when this is the top-level project, or with `-D{{NAME_SNAKE}}_BUILD_TESTS=ON`, so a project using the library through `add_subdirectory()` or `FetchContent` needs neither GoogleTest nor C++.
- The version comes from `project(... VERSION ...)` in `CMakeLists.txt`; the installed package accepts any request with the same major version.
- Warnings (`-Wall -Wextra -pedantic`) are on for gcc and clang, but don't fail the build.
